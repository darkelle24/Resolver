## But, pourquoi et périmètre

**Livrable :** Contrats versionnés des formats JSON et fixtures de référence.

documenter formats/versionnement des résultats, erreurs, traces, catalogue, provenance et export d'inspection ; fixer le sens des champs absents, `null`, `unavailable`, `truncated`, indices, colonnes UTF-8 et JSON Pointer.

Sources de départ : [VmEngine.cs](../../../src/central/runtime/VmEngine.cs) ; [Program.cs](../../../tests/Program.cs) ; [VmErrors.cs](../../../src/central/diagnostics/VmErrors.cs) ; [VmExplanation.cs](../../../src/central/diagnostics/VmExplanation.cs). Une capacité présente doit être qualifiée avant d’être réécrite ; l’intégration produit reste chez le consommateur.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.
