## But, pourquoi et périmètre

Les deux paquets 0.1.0 se construisent localement. Leur nuspec contient un commit, mais aucune URL de dépôt ni licence ; celui de Godot déclare une dépendance Core version="0.1.0", pas une plage exacte écrite [0.1.0]. Le script MSBuild retire les sources obsolètes dans addons/resolver. Ni cette lecture ni Pack ne prouvent une installation propre, une mise à niveau ou un retour de version.

**Résultat attendu :** Paquets traçables et essais reproductibles d’installation/mise à niveau/retour, dans des projets et caches isolés, avec inventaire des fichiers générés.

**Filiation :** R25 conservée ; absorbe les contrôles de provenance utiles de R26, sans audit général non motivé. Les [fiches historiques](../) restent intactes ; [dispositions](BILAN.md#traçabilité-des-anciens-identifiants).

**Sources actuelles à examiner :** [Directory.Build.props](../../../../Directory.Build.props) ; [Resolver.Core.csproj](../../../../core/Resolver.Core.csproj) ; [Resolver.Godot.csproj](../../../../packaging/Resolver.Godot.csproj) ; [Darkelle.Resolver.Godot.targets](../../../../packaging/build/Darkelle.Resolver.Godot.targets) ; [Pack.ps1](../../../../tools/Pack.ps1) ; [Resolver.Tests.csproj](../../../../tests/Resolver.Tests.csproj) ; [Resolver.Godot.Smoke.csproj](../../../../tests/godot-project/Resolver.Godot.Smoke.csproj). ## Approche et alternatives

Inspecter le nuspec réel, renseigner l’URL et le commit de provenance sans déduire une publication. Décider et tester si Core/Godot exigent la même version exacte ou une plage compatible ; ne pas changer ce contrat sans accord. Utiliser deux versions locales distinctes et un fichier devenu obsolète pour prouver upgrade/downgrade. Ne pas nettoyer de cache global ni modifier les addons d’un vrai consommateur. Réutiliser les projets de qualification existants ; la preuve moteur reste R21.
