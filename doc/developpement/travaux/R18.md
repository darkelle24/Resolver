## But, pourquoi et périmètre

**Livrable :** Fixtures consommables sans contexte de conversation et guide d’échange.

fournir des fixtures et, selon utilité, schémas JSON pour catalogue, erreur, source et explication ; préciser liens entre node_id, execution_id, path, source_hash, metadata_hash et snapshot exact. Identifier les données potentiellement sensibles à filtrer avant partage.

Sources de départ : [VmEngine.cs](../../../src/central/runtime/VmEngine.cs) ; [VmEngineNode.cs](../../../src/godot/VmEngineNode.cs) ; [VmCompilationMetadata.cs](../../../src/central/compiler/VmCompilationMetadata.cs) ; [node_catalog.json](../../../docs/node_catalog.json). Les [frontières du composant](../PROJET.md) et le [contexte versionné de planification](CONTEXTE.md) s’appliquent. Une capacité présente doit être qualifiée avant d’être réécrite ; l’intégration produit reste chez le consommateur.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.

lecture indépendante de fixtures : fragment fusionné, boucle, erreur de conversion Godot, trace tronquée et nœud custom ; aucun outil ne doit déduire « non exécuté » d'une simple absence dans une trace tronquée.
