## But, pourquoi et périmètre

**Livrable :** Corpus de régression reproductible couvrant les risques retenus.

compléter les tests selon les risques R03–R11 et R17 : JSON malformé/ambigu, Unicode, limites numériques, collections cycliques, graphes larges, effets de bord et permissions. Ajouter des cas générés reproductibles et comparaisons différentielles seulement lorsqu'une référence sémantique fiable existe.

Sources de départ : [Program.cs](../../../tests/Program.cs) ; [smoke.gd](../../../tests/godot/smoke.gd). Les [frontières du composant](../PROJET.md) et le [contexte versionné de planification](CONTEXTE.md) s’appliquent. Une capacité présente doit être qualifiée avant d’être réécrite ; l’intégration produit reste chez le consommateur.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.

chaque défaut trouvé possède une reproduction minimale ; graines/corpus conservés pour les tests générés ; résultats attendus issus du contrat, pas d'une copie de l'implémentation. Aucune obligation d'installer un framework pour obtenir un chiffre de couverture.
