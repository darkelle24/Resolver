préciser code de confiance, validation des arguments/retours, exceptions, mutations, réentrance, remplacement et durée de vie ; définir ce qui se passe si un callback bloque ou appelle une opération externe.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.

un callback n'est exécuté qu'une fois par appel prévu, y compris avec Explain ; exceptions et retours invalides deviennent les diagnostics annoncés. L'arrêt des instructions VM n'est pas vendu comme une interruption d'un callback bloqué ; une isolation supplémentaire reste une décision motivée par le besoin.
