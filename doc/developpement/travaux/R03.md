## But, pourquoi et périmètre

**Livrable :** Référence du langage JSON et des API publiques.

définir grammaire JSON, alias historiques, entrées directes/`inputs`, paramètres fixes, variables, ordre d'évaluation, court-circuit, `null`, champs inconnus et erreurs d'argument. Décrire aussi l'API C# et sa façade GDScript.

Sources de départ : [VmEngine.cs](../../../src/central/runtime/VmEngine.cs) ; [VmEngineNode.cs](../../../src/godot/VmEngineNode.cs) ; [Program.cs](../../../tests/Program.cs) ; [VmJsonCompiler.cs](../../../src/central/compiler/VmJsonCompiler.cs) ; [VmBuiltinNodes.cs](../../../src/central/nodes/VmBuiltinNodes.cs). Les [frontières du composant](../PROJET.md) et le [contexte versionné de planification](CONTEXTE.md) s’appliquent. Une capacité présente doit être qualifiée avant d’être réécrite ; l’intégration produit reste chez le consommateur.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.

chaque opération publique a un contrat d'entrées/sorties et un exemple valide/invalide vérifiable ; les usages actuellement compatibles sont conservés ou une migration est explicitement décidée.
