## But, pourquoi et périmètre

**Livrable :** Qualification des contrats de nœuds et compilateurs personnalisés.

couvrir noms/collisions, paramètres requis/enum, types d'entrée/sortie, variadiques, ordre, snapshot des définitions, remplacement et compatibilité d'anciens handles. Vérifier les compilateurs avancés et leur contrat de pile.

Sources de départ : [VmEngine.cs](../../../src/central/runtime/VmEngine.cs) ; [VmEngineNode.cs](../../../src/godot/VmEngineNode.cs) ; [Program.cs](../../../tests/Program.cs) ; [VmNodeRegistry.cs](../../../src/central/nodes/VmNodeRegistry.cs) ; [VmNodeCompilationContext.cs](../../../src/central/nodes/VmNodeCompilationContext.cs). Une capacité présente doit être qualifiée avant d’être réécrite ; l’intégration produit reste chez le consommateur.

## Approche et alternatives

Proposition : examiner les contrats existants, exécuter les scénarios ci-dessous et corriger uniquement les écarts démontrés. Alternative : conserver le comportement actuel lorsque sa preuve satisfait le besoin ; documenter la limite plutôt que modifier une API sans justification. Les arbitrages restent proposés tant qu’aucun accord réel n’est consigné.

une extension valide se documente et s'exécute sans modification centrale ; une définition invalide est refusée sans enregistrement partiel ; les traces et diagnostics restent exploitables.
