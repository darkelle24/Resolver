# Consignes — Resolver

Identifier la racine, la branche et les changements avec Git ; préserver le travail existant.
Commencer par [le routage IA](doc/ai/README.md), puis les seules références utiles.
Les [contraintes locales](doc/developpement/PROJET.md) définissent le périmètre du composant.

- Vérifier les prérequis consommés, les versions et les contrats avant modification.
- Distinguer proposition, accord explicite, réalisation et preuve. Ne pas inventer de tests, SHA, publication ou approbation.
- Conserver l'autorité et la documentation de chaque composant dans son propre dépôt. Documenter séparément l'intégration chez les consommateurs.
- Valider selon le changement ; une compilation ne remplace ni recette visuelle ni validation humaine.
- Suivre [l'organisation](doc/developpement/ORGANISATION.md) pour planifier, réaliser ou relire. Aucune publication ou fusion n'est implicite.
- Ce fichier appartient au socle versionné. Mettre les adaptations dans les contraintes locales ; examiner une mise à jour du socle avant adoption.
